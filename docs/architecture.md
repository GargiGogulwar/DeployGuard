# Architecture

## Components
| Component | Responsibility | Port |
|---|---|---|
| DeployGuard (FastAPI) | Dashboard, health/readiness, status, deployment history, Prometheus metrics | 8000 |
| SQLite (`/data`, Docker volume) | Deployment history (max 100 rows) | – |
| Prometheus | Scrapes `/metrics` every 5 s, evaluates alert rules | 9090 |
| Grafana | Pre-provisioned dashboard on top of Prometheus | 3000 |
| GitHub Actions | CI/CD orchestration | – |
| GHCR | Stores immutable images `sha-<commit>` | – |
| Terraform | Creates EC2 + security group | – |
| Ansible | Installs Docker, ships config, runs Compose, verifies | SSH 22 |

## Data flow
1. Operator pushes code → GitHub Actions builds/tests/containerizes.
2. On `main`, the image is pushed as `ghcr.io/<owner>/<repo>:sha-<commit>` (plus `latest` for convenience; **deployments never use `latest`** — the playbook rejects it).
3. Ansible copies `docker/docker-compose.prod.yml`, `monitoring/` and a root-only `.env` to the host and runs `docker compose up`.
4. Ansible verifies `/health`, `/ready` and that Prometheus reports the `deployguard` target `up`; if `DEPLOYGUARD_API_TOKEN` is set it records a `ci-cd` deployment entry.
5. Prometheus scrapes the app; Grafana queries Prometheus.

## Application endpoints
| Endpoint | Purpose | Codes |
|---|---|---|
| `GET /` | Dashboard | 200 |
| `GET /health` | Liveness | 200 |
| `GET /ready` | Readiness (DB check) | 200 / 503 |
| `GET /api/status` | App, build, readiness, latest deployments | 200 |
| `GET /api/deployments?limit=&source=` | History | 200 / 422 |
| `POST /api/deployments` | Record event (token) | 201 / 401 / 403 / 422 |
| `GET /metrics` | Prometheus exposition | 200 |

## Metrics (all prefixed `deployguard_` unless standard)
`deployguard_http_requests_total{method,path,status}`, `deployguard_http_request_duration_seconds_bucket/sum/count{method,path}`, `deployguard_service_ready`, `deployguard_build_info{version,git_sha,image_tag,environment}`, `deployguard_deployments_recorded_total{source,status}`, plus `process_*` and `python_*`. `up` is generated by Prometheus. The `path` label uses the route template or `unmatched`, which bounds label cardinality.

## Deployment-record honesty model
`runtime` = a process started (fact). `simulated` = demo data. `ci-cd` = written by Ansible after a real deployment. `runtime` cannot be forged through the API (rejected with 422). The dashboard's "Latest real deployment" card shows only `ci-cd` entries.

## Network and security boundaries
Security group: SSH from one CIDR; 8000/9090/3000 from `web_allowed_cidrs`. Inside Docker, services talk over the isolated `monitoring` bridge network by service name.
